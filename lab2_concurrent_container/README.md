# Практическая работа 2. Конкурентный контейнер

Несколько контейнеров одновременно работают с файлами в общем томе Docker.
Каждый контейнер в бесконечном цикле создаёт файл, ждёт 1 секунду, удаляет его и снова ждёт 1 секунду.

## Файлы
| Файл | Назначение |
|------|------------|
| `worker.sh` | скрипт на POSIX Shell, выполняемый в контейнере |
| `Dockerfile` | сборка образа на основе `debian:bookworm-slim` |
| `test.sh` | автоматическая проверка с N контейнерами |

## Ручной запуск
```sh
docker volume create shared-data                 # общий том
docker build -t concurrent-files .               # сборка образа
docker run -d --name w1 -v shared-data:/data concurrent-files
docker run -d --name w2 -v shared-data:/data concurrent-files
docker logs -f w1                                # журнал контейнера
docker stop w1 w2 && docker rm w1 w2
```

## Автоматическая проверка
```sh
./test.sh 1  20    # 1 контейнер, 20 секунд
./test.sh 10 20    # 10 контейнеров
./test.sh 50 30    # 50 контейнеров
```
Скрипт выводит число созданных файлов и число обнаруженных гонок (должно быть 0).

## Как выполнены требования
1. Цикл: создание файла → `sleep 1` → удаление → `sleep 1`.
2. Имя файла — первое свободное из `001`, `002`, `003`…
3. В файл записывается случайный идентификатор контейнера (из `/dev/urandom`, один на контейнер) и порядковый номер файла.
4. Поиск свободного имени и создание файла выполняются внутри `flock` на служебном файле `/data/.lock`.
   В блокировке выполняется только резервирование имени, данные записываются уже после её снятия — атомарная операция максимально короткая.
5. Контроль гонок: файл создаётся с `set -C` (запрет перезаписи); если имя уже занято, в журнал пишется `RACE CONDITION`.
   Без `flock` такие сообщения появляются, с `flock` — нет.
6. При `docker stop` (сигнал SIGTERM) контейнер удаляет свой текущий файл и завершается.
